1. QUICK FACTS
==========================================================================
Task: binary classification. Predict is_fraud (1 = fraud, 0 = not) for
each credit card transaction. Classical ML only (NOT deep learning).
Data: simulated transactions from the public Sparkov Data Generation
tool, github.com/namebrandon/Sparkov_Data_Generation (MIT license).
Models (8): logistic regression (baseline), decision tree, random forest, extra trees,
XGBoost, LightGBM, linear SVM (calibrated), Naive Bayes.
Imbalance handling: class weights (SMOTE optional, only if time allows).
Metrics: precision, recall, F1, PR-AUC, confusion matrix. Never lead with
accuracy (always-"not fraud" scores 99%+ if fraud is under 1%; measure
the real number and report it).
Key engineered features: haversine distance from home to merchant, time
features, customer age, per-customer history features (past only).
Split: by time (train earlier, validate, test later). No random split.
Demo: score hand-built synthetic transactions. NO real bank or personal
data anywhere (project rule).

10. PHASE 4 - FEATURE ENGINEERING
==========================================================================
Implement in src/fraud/features.py with unit tests. Every history
feature may use PAST transactions of the same cc_num ONLY (strictly
earlier unix_time).
Base features:
  amt, category (one-hot), city_pop, age_at_trans
Time features:
  hour, day_of_week, is_weekend, is_night (e.g., 22:00-05:59)
Location features:
  dist_home_mi = haversine(lat, long, merch_lat, merch_long)
History features (per cc_num, sorted by unix_time):
  secs_since_prev       = unix_time - previous unix_time
  dist_from_prev_mi     = haversine(prev merch coords, current coords)
  speed_mph_implied     = dist_from_prev_mi / hours since prev (cap)
  txn_count_1h, txn_count_24h = number of earlier txns in window
  amt_mean_past         = expanding mean of earlier amt
  amt_ratio_to_mean     = amt / amt_mean_past
  amt_zscore_past       = (amt - mean) / std of earlier amt
  first_txn_flag        = 1 if no earlier transaction
Rules for first transactions: fill history gaps with 0 or the global
median and set first_txn_flag; document the choice.
Leakage safeguards (test these in tests/):
  - Use shift() before expanding/rolling stats, or rolling windows with
    closed="left", so the current row never counts itself.
  - Assert no feature uses any row with a later unix_time.
  - Compute features on the full time-sorted table, THEN split by time.
Reference sketch:
  def haversine_mi(lat1, lon1, lat2, lon2):
      R = 3958.8
      p1, p2 = np.radians(lat1), np.radians(lat2)
      dphi = p2 - p1
      dlmb = np.radians(lon2) - np.radians(lon1)
      a = np.sin(dphi/2)**2 + np.cos(p1)*np.cos(p2)*np.sin(dlmb/2)**2
      return 2*R*np.arcsin(np.sqrt(a))
  g = df.sort_values(["cc_num","unix_time"]).groupby("cc_num")
  df["secs_since_prev"] = df["unix_time"] - g["unix_time"].shift(1)
  df["amt_mean_past"] = g["amt"].transform(
      lambda s: s.shift().expanding().mean())
  # 1h / 24h counts: rolling on a datetime index with closed="left"

11. PHASE 5 - SPLIT, MODELS, TUNING, EVALUATION
==========================================================================
SPLIT (time-based, by unix_time quantiles):
  train = earliest 70%, validation = next 15%, test = last 15%.
  Log the date boundaries and fraud counts in each part. The test set is
  touched ONCE at the end.
MODELS (all with class weighting, random_state=42):
  1. LogisticRegression(class_weight="balanced", max_iter=2000) with
     StandardScaler + one-hot.
  2. DecisionTreeClassifier(class_weight="balanced"); tune max_depth in
     {4, 6, 8, 12} and min_samples_leaf in {10, 50, 200}.
  3. RandomForestClassifier(class_weight="balanced_subsample",
     n_jobs=-1); tune n_estimators {200, 400}, max_depth {8, 12, None},
     min_samples_leaf {5, 20}.
  4. XGBClassifier(tree_method="hist", scale_pos_weight=neg/pos,
     eval_metric="aucpr") (or LightGBM). Tune max_depth {4, 6, 8},
     learning_rate {0.05, 0.1}, n_estimators with early stopping on the
     validation set, subsample/colsample {0.8, 1.0}.
TUNING: choose hyperparameters by validation PR-AUC (average
 precision). Use a 10-20% subsample of train for the search if runtime is
 long, then refit on full train. Keep search small (under ~20 min total).
THRESHOLD: for each model pick the probability threshold that maximizes
 F1 on the validation set. Also report results at the default 0.5.
FINAL EVALUATION on test, per model:
  precision, recall, F1, PR-AUC (average_precision_score), ROC-AUC,
  confusion matrix (tp, fp, fn, tn), accuracy (shown only to
  illustrate the trap), training time, and the PR curve (downsample to
  <= 200 points).
EXTRAS:
  - Feature importance: tree importance for RF/GB plus permutation
    importance on the validation set for the best model.
  - Per-transaction "drivers" for the web demo via occlusion: replace one
    feature group (amount, distance, time, history) with the customer's
    typical value and measure the change in probability (no SHAP needed).
  - Optional: SMOTE experiment on the best model if time allows.
DONE WHEN: a metrics table for all 4 models exists, the best model is
 identified by validation PR-AUC (state it plainly even if it is not
 gradient boosting), and every model is saved under models/.
